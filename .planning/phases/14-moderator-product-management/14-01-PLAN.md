<objective>
Open product management to moderators with full admin parity, per D-01..D-05 and D-12. Moderators get the same `/products` page, the same sidebar entry, and the same `/api/products/*` endpoints. The endpoints do not check canEdit or shifts, and the rest of the admin surface stays admin-only. The phase also adds an audit trail for every product mutation, for all roles, written in the same transaction as the change (D-06..D-08). It adds a case-insensitive duplicate-name guard that returns a 409 and shows it inline in the form (D-09, D-10), plus same-tab freshness for the sales-sheet product dropdowns (D-11).

Purpose: the tracer (Task 1) proves the whole path first: moderator nav → route → widened RBAC → transactional create + audit row. Tasks 2 and 3 then extend the audit and the duplicate check to every mutation (backend) and to the modal and cache (frontend).

Output: rest-params `requireRole`, audited and duplicate-checked `products.ts`, `products.check.ts` (the phase's one runnable check), the moderator route and nav, the ProductModal 409 inline error, and `['catalog-products']` invalidation on all four product mutations.

No schema change: `AuditLog` is already generic (`tableName`, `rowId`, nullable `saleId`). Toggle and delete map to `action: 'update'` with `fieldName: 'isActive'` / `'deletedAt'`, per CONTEXT.md discretion. No plan touches `schema.prisma`, so no schema push task is needed.
</objective>
