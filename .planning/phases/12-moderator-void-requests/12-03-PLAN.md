<objective>
Add the moderator-facing half of the Void Request workflow to the existing Sales sheet: a per-row "Void Request" action on the moderator's own active rows, a small reason-entry dialog modeled on the existing `VoidConfirmDialog`, and the pending-state gating that disables the button while a request is already awaiting review.

Purpose: this is the entry point of the whole feature — the moderator's replacement for the direct void they are not allowed to perform (ROLES-06). It must respect CONTEXT.md D-01 (own active rows only), D-02 (one pending per row), and D-07 (no other moderator-side indicator).

Output: `VoidRequestDialog.tsx`; new dialog UI state on `salesEditStore`; a gated "Void Request" button in `SalesTable`'s Actions cell; the pending-sale-ids query and dialog mount on `SalesPage`.
</objective>
